# 凝练研究 idea

用户手里有一个初步 idea（一句话的方向或猜想），请你把它整理成**可以拿去组会讨论、判断值不值得做**的版本。用户会逐项修改，所以要具体、诚实，不要凑字数。

## 准备

1. `./p2b idea show <id>`：看标题、一句话、已有内容，以及**来源**——当时的想法、讨论消息、论文。凝练要忠于这些来源里用户的原意。
2. 读关联论文的快读卡和关键页：`./p2b show paper <id>`、`./p2b text <id> --pages ...`。
3. 在库里找相关工作：`./p2b search "关键词"`、`./p2b papers --topic "VLA"`。库里没有、但你知道的重要相关工作，可以提，但要标注"（库外，未核对）"。

## 提交格式

```json
{
  "title": "一句话能说清的 idea 名称（≤30 字）",
  "summary": "一句话：做什么、为什么可能有效",
  "problem": "要解决的问题，为什么现在的方法不够（带证据）",
  "insight": "核心洞见：别人没想到/没做到的那个关键点",
  "approach": "方法思路：2-5 步，输入输出、关键模块",
  "novelty": "和已有工作的区别，逐篇对比 [arxiv:2410.24164 p.3]",
  "experiment": "最小验证实验：用什么数据/平台、对比谁、看什么指标、多大算成功",
  "risks": "风险与未知：最可能失败的原因、需要先确认的假设"
}
```

- 引用库里的论文写成 `[arxiv:2410.24164 p.3]` 或 `[doi:10.xxx]`。校验会检查被引论文是否在库里；被引的论文会自动加入这个 idea 的来源。
- 用户的想法写成 `[想法 2026-10-16]`。
- 不确定的地方写"待确认：……"，不要编数字。
- 提交：`./p2b idea put <id> --file /tmp/idea.json --base-rev <revision>`。返回"内容已被修改"说明用户刚改过，重新 `show` 后在用户版本的基础上再改。

完成后回复三行以内：最关键的洞见、最小验证实验、最大的风险。
