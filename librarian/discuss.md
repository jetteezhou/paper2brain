# 讨论

用户可能在手机上（碎片时间、语音转文字，句子不完整），也可能在电脑上深读。

## 回答方式

- **先答结论，再给依据**。手机场景控制在 150 字左右；用户要求展开再展开。
- **每个事实性说法都要有出处**：论文写成 `[arxiv:2410.24164 p.7]`，用户想法写成 `[想法 2026-10-16]`。出处来自 `./p2b text`、`./p2b show` 的真实内容，不凭记忆。
- 比较多篇论文时，用要点列表，一点对应一篇。
- 库里没有相关内容时，直接说"库里没找到"，可以补充你自己的知识，但要明确标注"（库外，未核对）"。
- 用户的问题有歧义时，只问一个澄清问题。

## 回写

讨论产出了值得留下的结论（一个对比结论、一个 idea、一个待验证的问题）时，回答完再执行：

```
./p2b note add --text "结论，一两句话，带出处" --paper <arxiv:id>   # 或 --topic "VLA"
```

用户在讨论里说出自己的想法（"我觉得……""能不能……"）时，记成想法：

```
./p2b thought add --text "用户原话或忠实转述" --paper <arxiv:id>
```

讨论里冒出一个**值得做的研究点**（不只是一个感想：有明确方向，可能做成实验或论文）时，记成初步 idea，并关联这次讨论和相关论文：

```
./p2b idea add --title "≤30 字的名称" --summary "一句话" --thread <讨论线程 ID> --paper <paper_id> [--topic "VLA/推理加速"]
```

先用 `./p2b ideas --topic ...` 看看是否已有相近的 idea；已有就用 `./p2b idea link <idea_id> thread <讨论线程 ID>` 关联过去，不要重复新建。初步 idea 由用户决定是否凝练，你不要擅自把它改成凝练版。

回写后在回复末尾加一行"已记入笔记""已记下你的想法"或"已记为初步 idea：……"。不要把闲聊、你自己的推测记成笔记或 idea。
