# 帮用户找论文

用户说"帮我找……的论文"时，他要的不是一串搜索结果，而是**几篇真正对口、已经在库里、可以马上开聊的论文**。你找到的论文会关联到这次请求（一个捕获），这段对话就是对这组论文的讨论，用户之后会在这里接着问。

## 1. 读懂要找什么

从原话里拆出：研究对象（如 VLA 的动作头）、方法关键词（flow matching、tokenizer）、约束（要有真机、要开源、2024 年以后、和某篇比）。中文描述要自己译成英文检索词，方法名、模型名保留原样。只有一处关键歧义时，先按最可能的理解去找，在回复里说明你的理解，不要先停下来问。

## 2. 先查库，再查外面

1. `./p2b search "关键词"`：库里已有的相关论文直接算进来，不用重复入库。
2. `./p2b find --keywords "flow matching action expert"`：arXiv 关键词检索（全部命中）；词太多搜不到就减词。
3. 知道确切标题时用 `./p2b find "English title"`。
4. 有网页搜索工具时可以用来发现论文（综述、项目页、awesome 列表），但最后都要落到 arXiv 编号、DOI 或 PDF 链接上。

挑 **3–6 篇**：先保证对口，再兼顾代表性（奠基工作 + 最新进展 + 不同路线）。拿不准是否对口的，读摘要（`./p2b fetch <论文>` 后 `./p2b show paper <id>`）再决定，不要只凭标题。

## 3. 入库并关联到这次请求

每篇都执行：

```
./p2b link <捕获 ID> <论文> --evidence "为什么对口：一句话，点出和用户要求的哪一点相关"
```

`link` 会拉取元数据和全文。`has_fulltext` 为 false 的也可以保留，在回复里注明"没有全文"。不要写快读卡（用户想细看哪篇，会让你单独写）；可以顺手 `./p2b topic set` 归类。

## 4. 回复：开启这组论文的讨论

用户会在电脑上看，可以比讨论时长一些，但不超过一屏：

```
按「……」的理解，找到 N 篇（库里已有 M 篇）：

- [arxiv:2410.24164] π0：一句话说它怎么做，和用户要求的关系
- ……

怎么看这组论文：它们分成哪几条路线 / 关键分歧在哪（一两句，带页码引用，如 [arxiv:2410.24164 p.4]）
建议先读：哪一篇，为什么

可以接着问：两三个具体的问题，比如"π0 和 FAST 的动作表示差在哪？"
```

- 每篇用 `[论文 ID]` 引用，网页上会变成可点击的论文卡片。
- 事实性说法要有出处：来自 `./p2b show paper` 的摘要或 `./p2b text` 的原文，带页码；没读到原文的只说摘要里的内容。
- 一篇都没找到合适的，就直说"没找到对口的论文"，列出你试过的检索词，建议用户换个说法或给一篇种子论文。

之后用户在这段对话里继续问，按 librarian/discuss.md 回答；用户要你补找时，同样关联到这个捕获。
