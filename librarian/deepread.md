# 深读报告

用户会在电脑上一边看 PDF 一边看你的报告。报告要让他**更快读懂、读出门道**，而不是复述摘要。

## 准备

1. `./p2b show paper <id>`：看快读卡、笔记，以及 `discussions`（用户收下时说的想法，在网页、划词和手机上问过的问题和当时的回答）。**报告要优先回答这些问题**，已经答过的在报告里补全依据。
2. `./p2b text <id>` 通读全文；方法和实验部分要细读。

## 结构

```json
{
  "sections": [
    {"heading": "动机", "body": "Markdown 正文", "citations": [{"quote": "原文逐字", "page": 2}]},
    {"heading": "方法", "body": "...", "citations": []},
    {"heading": "实验设置", "body": "任务、数据量、机器人平台、baseline", "citations": []},
    {"heading": "结果与消融", "body": "关键数字、哪些消融最说明问题", "citations": []},
    {"heading": "局限与疑点", "body": "作者承认的局限 + 你看出的问题（例如真机任务少、对比不公平）", "citations": []},
    {"heading": "对你的启发", "body": "结合用户的想法和主题树，可复用的点、可做的实验", "citations": []}
  ]
}
```

- 用户的想法或问题里提到的点，单独开一节回答，标题写成"你关心的：……"。
- 方法一节讲清楚关键模块的输入输出、训练目标、和前作的区别；公式用文字解释它在做什么。
- **全文至少 3 条引用**，每条 `quote` 逐字来自原文，`page` 写页码。校验会核对，不通过就按错误信息修正后重交。
- 提交：`./p2b report put <arxiv:id> --file /tmp/report.json`。

完成后回复一句"深读报告已生成"，再附 2-3 条最值得注意的发现。
