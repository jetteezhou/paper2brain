# 深读报告

用户会在电脑上一边看 PDF 一边看你的报告。报告要让他**更快读懂、读出门道**，而不是复述摘要。

## 准备

1. `./p2b show paper <id>`：看快读卡、笔记，以及 `discussions`（用户收下时说的想法，在网页、划词和手机上问过的问题和当时的回答）。**报告要优先回答这些问题**，已经答过的在报告里补全依据。
2. `./p2b text <id>` 通读全文；方法和实验部分要细读。

## 结构

报告是在原文上"划句"读出来的：每一段（`point`）都是你从原文某几句话读出的一个要点，`citations` 就是划下的那几句。用户在 PDF 上会看到这些句子按节着色划线，点句子跳到报告里对应的段，点段后的页码跳回原句。

```json
{
  "sections": [
    {"heading": "动机", "points": [
      {"text": "Markdown，一段讲一个要点。依据第一句原文的这句话后面标上[1]，另一句依据第二句[2]。",
       "citations": [{"quote": "原文逐字的一整句", "page": 2}, {"quote": "另一整句", "page": 3}]}
    ]},
    {"heading": "方法", "points": []},
    {"heading": "实验设置", "points": []},
    {"heading": "结果与消融", "points": []},
    {"heading": "局限与疑点", "points": []},
    {"heading": "对你的启发", "points": []}
  ]
}
```

各节写什么：实验设置写任务、数据量、机器人平台、baseline；结果与消融写关键数字、哪些消融最说明问题；局限与疑点写作者承认的局限 + 你看出的问题（例如真机任务少、对比不公平）；对你的启发结合用户的想法和主题树，写可复用的点、可做的实验。

- 用户的想法或问题里提到的点，单独开一节回答，标题写成"你关心的：……"。
- 方法一节讲清楚关键模块的输入输出、训练目标、和前作的区别；公式用文字解释它在做什么。
- 正文里用 `[k]` 标出第 k 条引用支撑的是哪句话，紧跟在那句话后面；网页会把它显示成可点回原文的页码。每条引用都要标。
- **每一段至少 1 条引用**，包括"局限与疑点""对你的启发"：引你这个判断所依据的那句原文。`quote` 逐字来自原文，尽量是完整的一句（不要只截半句或一个词组），`page` 写页码。一段一个要点（1–3 句话，不超过 300 字、最多 3 条引用），宁可多分几段，不要一段堆好几件事；列表的每一项通常就是单独一段。校验会核对，不通过就按错误信息修正后重交。
- 提交：`./p2b report put <arxiv:id> --file /tmp/report.json`。

完成后回复一句"深读报告已生成"，再附 2-3 条最值得注意的发现。
